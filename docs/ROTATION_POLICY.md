# 可配置账号轮换策略

策略配置写在运行目录的 `panel-config.json`。规则只保存账户的稳定 `sha256:` 标识及设置，不保存邮箱、备注或 token。账户显示顺序变化不会改变绑定。仓库示例的全 1、2、3 标识是虚拟数据，不能直接绑定真实账户。

## 在界面中设置

桌面端打开「策略」页，在「切换规则」里选「自定义账户规则」。设置日常/备用角色，用表格右侧的上移、下移调整组内顺序，填写默认阈值和单号覆盖值，然后点底部的「保存策略」。页面上的改动直接进入草稿，不需要额外的“应用”步骤；「放弃修改」恢复为已保存的策略。自定义规则下，账号详情里的「编辑角色规则…」会跳到「策略」页。

网页版在策略区勾选「启用自定义账户规则」，直接编辑账户表和全局设置，再点击「保存策略」。两端均支持放弃草稿，自动刷新不覆盖未保存输入。保存期间禁止继续编辑，失败保留草稿。

所有账户必须分配角色，至少保留一个日常号。可以配置多个备用号，也可以不设备用号。保存不会立即切号，下一轮检查时执行。自定义模式下，基础储备号和等待控件停用，旧角色按钮引导到规则编辑器。

账户增删或身份改变后，保存会重新核对账户池。不完整或过期的绑定返回 `ACCOUNT_POOL_CHANGED`，原配置不变。刷新后为新账户指定角色，移除已删除账户的绑定，再保存。运行中的策略遇到失效绑定也会停止变更并记录错误，避免切错号。

## 规则含义

| 设置 | 范围 / 默认值 | 执行方式 |
| --- | --- | --- |
| 日常号选择 | 循环 / 优先；默认循环 | 循环从当前日常号之后选；优先从列表首位选。健康的当前日常号继续使用，不为排序主动切号。 |
| 5H、7 天剩余额度阈值 | 剩余 0–99%；默认 0% | 任一窗口剩余 ≤ 阈值时不作为健康候选，进入切换判断。例如 10% 表示剩余不超过 10% 时提前切号；0% 表示用完再切。等待刷新和最短切换间隔仍然生效。 |
| 等待刷新 | 0–600 分钟；默认继承基础等待值 | 达到 5H 阈值、周额度正常且距重置严格小于阈值时等待。0 表示不等待，等于阈值时不等待。 |
| 最短切换间隔 | 0–3600 秒；默认 600 秒 | 防止频繁切号，运行时硬阻塞绕过此限制。 |
| 日常号恢复后回切 | 默认开启 | 使用备用号时回到健康日常号；关闭后继续使用健康的当前备用号。 |
| 单号覆盖 | 5H、周阈值、等待时间 | 留空继承全局值。单号等待可明确填 0。 |

例如，全局 5H 剩余阈值填 10，表示某个账号的 5H 剩余降到 10% 或更低时进入换号判断。该账号的“等待刷新（分）”填 60 后，如果它的 5H 窗口将在 60 分钟内恢复，策略会先等待恢复；如果距离恢复更久，才继续选择其他健康账号。这个等待值只影响触发阈值的账号，不会阻止 7 天额度耗尽、认证失效或运行时硬故障的切换。

日常号均不可用时，先检查是否有值得等待的日常号，再按备用列表顺序选健康备用号。运行时 429、认证失效、网络冷却等硬阻塞，以及周额度达到阈值，不能被等待规则掩盖。手动暂停的账户不会因被设为备用而自动恢复。

等待或受最短间隔限制时，不会因提前切换的软阈值暂停仍有额度的当前号；实际已用 100% 的账户可以被暂停。额度未知或查询失败不会被当作恢复，自定义模式也不会仅凭旧快照的重置时间已过就推断新额度充足，需要后续额度观测确认。

## 配置结构与维护

界面填写的是剩余比例，存储仍使用兼容旧版本的已用比例字段：`shortUsedPercent = 100 - 5H剩余阈值`，`weeklyUsedPercent = 100 - 7天剩余阈值`。例如界面填 10%，配置保存 90；旧配置保存 95，界面显示 5%。单号覆盖采用相同换算，留空继续继承全局值。上限为 99%，避免把刚刷新的满额账户也排除。

通常由界面生成配置，无需手写 JSON。以下展示结构，`<...>` 必须替换为实际绑定标识：

```json
{
  "autoSwitch": true,
  "allowFailover": true,
  "rotation": {
    "version": 1,
    "mode": "daily-reserve",
    "daily": ["sha256:<daily-key-1>", "sha256:<daily-key-2>"],
    "reserve": ["sha256:<reserve-key>"],
    "waitBeforeSwitchMin": 60,
    "minGapSec": 600,
    "shortUsedPercent": 100,
    "weeklyUsedPercent": 100,
    "returnToDaily": true,
    "dailySelection": "cycle",
    "accountRules": {
      "sha256:<daily-key-1>": { "shortUsedPercent": 95, "waitBeforeSwitchMin": 0 }
    }
  }
}
```

`rotation: null` 关闭自定义模式并恢复基础策略，不自动恢复手动暂停状态。省略 `rotation` 的旧客户端保存操作会保留现有规则，局部保存也保留未提交的基础字段和其他配置。

验证与执行集中在 `panel/lib/rotation-policy.js`。不支持的版本、字段或阈值会被拒绝，不执行用户脚本。网页版编辑器是 `panel/public/modules/rotation-editor.mjs`，桌面端是 `panel/app/PolicyView.cs`（整页）和 `panel/app/RotationEditorControl.cs`（自定义规则编辑器），两端共用后端与决策链。增加规则时同步扩充验证、决策、两端控件和行为测试，不在 PowerShell 中复制判断。

保存错误包含 `ROTATION_CONFIG_INVALID`、`ACCOUNT_POOL_CHANGED`、`ACCOUNT_POLICY_READ_FAILED` 或 `ACCOUNT_OPERATION_BUSY`。自定义模式调用旧角色接口会得到 `CUSTOM_ROLE_RULE_REQUIRED`。配置采用原子替换，保存响应包含完整已接受规则；额度快照也读取当前策略，避免旧缓存覆盖新设置。

开发预览使用 `npm run dev:panel`，只连接合成 mock 数据；真实账号目录由 `CODEX_HOME` 单独指定。生产认证备份使用 Windows 当前用户 DPAPI 加密，测试环境也只使用 AES-GCM 密文，不会回退到明文。
