Codex 额度面板 · 使用说明（v2.0 原生版）
==========================================

一、怎么打开
  1) 桌面「Codex 额度面板」双击  —— 推荐
  2) Win 键 → 搜索 codex / quota / 额度 → "Codex Quota Panel"
  3) Win + R → 输入 CodexQuota 回车
  4) 网页版兜底：桌面「Codex 额度面板（网页版）」，或浏览器打开 http://127.0.0.1:8766/

  程序是原生 Windows 应用（WinForms），不嵌浏览器；启动时会自动检查并在需要时
  拉起本地服务（node server.js），不需要你手动开服务。

二、界面
  左侧「账号池」：每个账号一行，显示 角色（日常/储备/暂停）、5 小时剩余、7 天剩余、
  状态（使用中/已暂停）。点一行，右侧显示详情。
  右侧四个页签：
    · 账号详情：邮箱、计划、角色、备注、上次使用、状态说明、两个额度进度条、操作按钮
    （切换到此账号 / 暂停账号 / 设为储备 / 修改备注 / 刷新额度）
    · 事件：策略脚本与路由的事件流（LIMIT / WAIT / SWITCH / OK / GUARD …）
    · 策略：自动切号开关、5 小时耗尽的等待阈值（分钟）、储备号选择、保存
    · 路由：本地路由状态（PID/请求/轮转/错误）、重启路由、重新绑定、添加账号
  底部状态栏：服务状态、当前账号、本周剩余额度与预算、路由状态、更新时间。

三、关于额度与自动切号（和网页版一致）
  · 规则：5 小时额度耗尽且距重置 >= 阈值（默认 60 分钟）才切号；不足 60 分钟就等，
    避免为了几十分钟暂停项目、还要让新账号重读上下文。
  · 日常号全部耗尽才动用「储备号」（储备号，无 5 小时限速，留给周额度重置后一波用）。
  · 全部耗尽：事件页出现 DEAD 记录并给出最早恢复时间。
  · 每周预算线：三个账号合计按 7 天折算（状态栏会算"按当前速度什么时候见底"）。

四、添加账号（重要，修复了会导致卡死的旧实现）
  · 点「添加账号」后，会确认一次，然后打开**一个独立的命令行窗口**（标题 Codex Add Account），
    浏览器会自动打开让你登录；登录完成后关闭那个命令行窗口，再点一下「刷新额度」。
  · 同一时间只会存在一个登录窗口（再点会提示"登录窗口已经打开了"）。
  · 登录窗口超过 15 分钟没结束会被自动关掉，防止再出现"无限弹出窗口"。
  · 旧版本（v1.x）用隐藏进程启动 CLI，CLI 没有终端会把交互菜单读成 EOF 并循环打开浏览器，
    导致窗口风暴；v2.0 已改为可见终端 + 单飞 + 看门狗。

五、报错怎么理解
  · 路由卡偶尔出现"有错误 / 曾重试，已恢复"：上游网络抖动（代理/OpenAI 侧），
    路由会自动重试；后续请求成功后会显示灰色"曾重试，已恢复"，不用处理。
  · 真的卡住（2 分钟无进展）会显示红色"有错误"，后台会自动重启一次路由；
    也可以手动点「路由 → 重启路由」立刻清掉旧记录。

六、托盘与关窗
  · 点窗口的 X 不会退出，而是缩到右下角托盘；托盘图标双击打开，右键有
    打开面板 / 刷新 / 添加账号 / 网页版 / 退出。
  · 真正退出请用托盘菜单的「退出」。

七、开机自启
  · 默认**不开启**（按你的要求）。需要时可在托盘菜单里开；程序会记住上次的选择。

八、路径与日志
  · 程序：%USERPROFILE%\.codex\multi-auth\panel\desktop\CodexQuota.exe
  · 配置：同目录 app-config.json（窗口位置/大小、node 路径、服务地址）
  · 日志：同目录 app.log（程序）、panel\app-server.log（本地服务）
  · 策略脚本与日志：%USERPROFILE%\.codex\multi-auth\quota-policy.ps1 / quota-policy.log

九、安全边界
  · 本地服务只监听 127.0.0.1，网页版带一次性 token（刷新后重生成），别把 8766 端口暴露到公网。
  · 面板里的账号凭据来自 codex-multi-auth，面板只做管理与切换，不保存你的密码。
--- v2.1 更新（2026-10-24）----------------------------------------------------
1) 「添加账号」加了两道闸门：先弹风险确认框，必须勾选「我已了解风险，继续打开登录窗口」
   才能点「继续添加」；登录会在一个独立的命令行窗口里进行，同一时间只会有一个，
   超过 15 分钟未完成会自动结束（避免重复开窗口）。
2) 「策略」页新增一行状态：自动切号脚本：上次运行 时间 · 状态（OK / SWITCH / WAIT /
   GUARD / ERROR / SWITCH-FAILED）。红色表示需要处理，请对照「事件」页最新记录。
   —— 这条是为了让"自动切号悄悄失效"能被立刻看见。
3) 「重启路由 / 重新绑定」现在都有二次确认；失败会弹窗说明原因，不会再显示成"已刷新"。
4) 策略脚本修了一个严重问题：以前切号只改暂停状态、没有真正切换当前账号，导致
   切完后路由仍指向已被暂停的账号，随后每 5 分钟报"没有选中账号"且无人察觉。
   现在会真正 switch 并校验 activeIndex，失败自动回滚并记 SWITCH-FAILED。
   另外：储备号在用时，一旦有日常号恢复额度，会自动切回日常号，避免把储备额度吃掉。
5) 服务端「刷新额度」等接口的健壮性修复（超长请求不再卡死、策略文件 BOM 兼容等）。

测试建议：先用「刷新额度」看三个账号是否正常；再点「添加账号」确认闸门（取消即可）；
策略页确认状态行显示 OK；路由页确认 PID/端口正常。

[ v2.8 - 2026-10-24 23:35 ] 性能与托盘修复（实测数据）
一、打开速度
- 旧版：启动时先 POST /api/refresh 再 GET state，最慢 8~37 秒才出画面。
- 新版：先画磁盘缓存（panel-cache.json），再后台刷新；实测 窗口出现 343~408ms、首次绘制 86~107ms。
- 状态栏会显示"（缓存 N 秒前）"，说明这是缓存数据、后台正在更新。
二、刷新额度
- 旧版：POST /api/refresh + 紧跟 GET ?force=1，两遍完整构建（实测 5814ms，最差 32s）。
- 新版：只发一次 POST 并直接用返回的 state；实测 3018~4138ms。并发刷新会复用同一次构建，不再排队翻倍。
- 服务端新增 60 秒缓存 + 面板缓存文件：浏览器版/桌面版共用，关掉再开仍是秒出。
三、托盘图标残留
- 根因：之前我用 Stop-Process 强杀，进程没机会发 NIM_DELETE，Explorer 就留一个"幽灵图标"（鼠标划过才消失）。正常退出路径本身没问题。
- 已修：统一 DisposeTray()（幂等，退出/关闭/Dispose 三处共用）+ IconFactory 补 DestroyIcon 修 HICON 泄漏。
- 实测：优雅关闭后托盘项立即消失，连开连关 2 轮均无新幽灵。
- 注意：现在托盘里若还有 1 个旧幽灵（来自之前被强杀的实例），鼠标划过它就会消失；那是历史残留。
- 建议：以后退出请点窗口 X 或托盘菜单"退出"，不要用任务管理器强杀。
四、已知正常现象
- 刷新额度时单次 CLI upstream 查询约 3~4 秒，属上游接口耗时，不是软件卡。
- 若某项额度接口返回 429，该行会显示"额度接口 429，暂时读不到数据"，点刷新可重试。

[ v2.12 - 2026-10-25 00:45 ] 403 / 409 两个故障的根因与修复
1. Codex 报 "unexpected status 403 Forbidden: Selected model is not advertised by an eligible account"
   根因：看门狗 ensure-router.ps1 里硬编码检查旧端口 56014（实际绑定端口是 61908），每 5 分钟误判
   "路由已停"，多启一个实例 -> EADDRINUSE -> 路由状态文件被写成 stopped/error -> Codex 请求偶尔没有可用账号。
   修复：ensure-router.ps1 改为从 app-bind\runtime-rotation-app-bind.json 读真实端口，按"node 进程 + --port"
   双条件判活，只有确实不在时才拉起；实测"杀路由 -> 看门狗恢复 -> 请求 ok"。
2. 点"添加账号"提示 "登录窗口已经打开了（PID xxx）"（浏览器授权页早关了还一直弹）
   根因：旧的登录 cmd 残留 + 旧判定只看"cmd 存在 + state 新鲜"。
   修复：现在分三态——真有登录进程在跑才提示"正在授权中"；只有残留窗口且超过 90 秒会自动清理并重新打开；
   state 刚写入（<90 秒）会提示稍等。新增"取消登录"会自动杀窗口、删状态文件。
3. "添加账号"现在默认直接打开浏览器授权（不再弹确认框）；试运行版本在菜单"账号 → 添加账号（试运行，不真登录）"。
4. 加载时间：打开软件先渲染磁盘缓存（首屏约 0.1 秒），刷新额度 3~4 秒（后台单飞，不重复跑），
   重启路由会轮询到真正就绪再返回（约 6 秒），不再固定等待。
